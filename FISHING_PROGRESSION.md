# Пруд Карпа, боссы и ограниченная экономика

Доработка 17.11.2026 опубликована после отдельного разрешения «залевай»: production commit 679004d, API/web carp-679004d, миграция 0004. Данные не сбрасывались; [результат выкладки](<DEPLOYED_ZEROX.md>) содержит точные проверки и ограничения. Исходный локальный этап и план ниже сохранены для контекста.

## Игровой контракт

- Пруд Карпа открывается с удочки 2 уровня: туманный причал, собственная байка, карп в пуле 38%, стоимость обычной рыбы ×1,25. Это вероятность вида только после успешного вываживания, не гарантия улова.
- Четыре босса: Старый Карп (ур. 2, 500 очков), Страж петли (ур. 3, 750), Хозяин глубины (ур. 4, 1200), Хранитель коммита (ур. 5, 1800). Награда — одна рыба в садке; очки приходят только после продажи. Персонаж не влияет на шансы.
- Клиент передаёт режим и журнал управления, но не награду, вид или сложность. Сервер воспроизводит вываживание, назначает босса по локации и проверяет уровень.
- Общие для всех локаций лимиты: 25 обычных попыток, не более 10 обычных уловов, 3 попытки боссов за сутки, награда каждого босса один раз в день. Между забросами 45 секунд. Неудачи и истечения времени расходуют начатую попытку.
- Четыре спортивные skill-игры делят 40 попыток в день. Случайные игры не превращены в игры с лимитом рыбалки.
- Сутки определяет PostgreSQL по Asia/Yekaterinburg; смена часов телефона, локации, клиента или API worker квоту не обновляет. Начатый до полуночи улов также проверяет лимит дня получения.
- Идемпотентный повтор возвращает сохранённый ответ без второй попытки/рыбы/выплаты. Операции сериализуются существующими User → Wallet locks; новая квота при первом обращении восстанавливает текущие расходы из истории. Старые активные раунды сохраняются.
- Это ограничение экономики, а не доказанная защита от ботов или мультиаккаунтов.

## Музыка

Плеер содержит только метаданные: «Пыяла», АИГЕЛ, альбом «Пыяла». Фонограммы в проект не добавлялись, музыка не скачивалась. Без файла воспроизведение и громкость отключены. Нет autoplay.

После отдельного предоставления разрешённого файла можно задать VITE_CARP_POND_AUDIO_PATH локальным абсолютным путём сайта (например, /audio/carp-pond.mp3) и пересобрать frontend. Внешние URL, protocol-relative URL, обратные слеши и управляющие символы отклоняются. Плеер запускается только нажатием при включённом звуке и ставится на паузу при скрытии страницы, выключении звука, смене локации или выходе из раздела. Без фонограммы слышимость, декодирование и поведение реального аудио в Telegram не проверены.

## Исправления этого прохода

- Известный 429 от серверных квот больше не удерживает pending-операцию и не блокирует все остальные игры. Неизвестные сетевые ошибки и общий rate limit сохраняют прежний ключ повтора.
- Фильтры каталога переносятся на новую строку вместо скрытых за горизонтальной прокруткой кнопок.
- Запрет выделения ограничен кнопками рыбалки; текст приложения и поля по-прежнему доступны для копирования.
- Публичный dev-fixture обновляется из настоящих серверных таблиц, включая Пруд Карпа, боссов и квоты, без доступа к пользовательским данным.

## Проверки и ограничения

В browser_* отдельно воспроизведены свежий отказ fishing_attempt_daily_limit и повтор сохранённого отказа: pending снят, выбор локации доступен, баланс не изменился. Для Пруда Карпа видны босс и отключённые кнопки плеера без src. Проверен экран недоступного расписания.

Production-сборка TypeScript/Vite успешна. 58 офлайн-тестов правил, вываживания, квот, идемпотентности и core-безопасности прошли через backend/run_offline_checks.py с синтетической конфигурацией. В офлайн-проходе dotenv и DB-подключения заблокированы. После согласования релиза дополнительно прошли 9 PostgreSQL integration tests на одноразовой БД, upgrade 0003 → 0004 с сохранением синтетических записей и runtime-проверка прав новой таблицы в production.

Реальные Telegram iOS/Android, производительность слабых телефонов, полноценная многопроцессная нагрузка и restore из backup требуют отдельной приёмки; integration tests покрывают часть конкурентных инвариантов, а не всю нагрузочную модель. Мобильная ширина в браузере не заменяет физический телефон.
