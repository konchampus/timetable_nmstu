# Пара · Telegram Mini App расписания МГТУ

Неофициальный сервис. **Изолированно развёрнут на zerox-prod:** [Mini App](https://timetaaaas2ble.chickenkiller.com/) · [Telegram-бот](https://t.me/timetable_casino_nmstu_bot). Сборка, HTTPS/API health и конкретные живые обращения поиска/расписаний подтверждены; полная приёмка и тестовые suites не выполнены. vices-prod и старый бот коллоквиума не изменены. Название «Пара» рабочее. [Фактическое развёртывание и смена токена](<DEPLOYED_ZEROX.md>); [история восстановления](<IMPLEMENTATION_STATUS.md>).

## Возможности исходной реализации

- Python/aiogram-бот: сегодня, завтра, неделя, ближайшая пара, поиск и управление уведомлениями.
- React/TypeScript Mini App: Сегодня, Неделя, Поиск, Игры, Профиль; темы Telegram, мобильная/desktop навигация.
- Реальный адаптер timetable.magtu.ru: группы/подгруппы, преподаватели, обе недели, времена/аудитории, общий поток, кэш, подтверждение изменений двумя снимками, сохранённая версия при сбое.
- Единые настройки уведомлений: перед парой, утро, вечер на завтра, изменения, окончание пары, тихие часы, дни, пауза, полное отключение из обоих интерфейсов.
- Приватные заметки и ДЗ: версии, поиск по всем записям/предмету, фильтр типа и страницы; подтверждение выхода, неизменный payload при повторе неизвестного сохранения. Связь с исходным расписанием сохраняется; исчезнувшая пара не удаляет запись. Для нового поля нужна отдельная [миграция](<backend/alembic/versions/0002_note_source.py>), пока не применённая.
- 12 игр: слоты, рыбалка, кости, дартс, боулинг, баскетбол, футбол, монетка, европейская рулетка, блэкджек, сапёр и колесо. Только бесплатные игровые очки, без Stars/денег/вывода/переводов/ценных призов.
- Настоящие процедурные Three.js сцены и Web Audio, независимые от серверных результатов; уменьшенная анимация, экономичный режим, отключение звука, пауза в фоне/скрытой вкладке и DOM fallback без WebGL.
- Рыбалка с пятью уровнями удочки, пятью видами/редкостями улова, весом, коллекцией, продажей и рекордом. Ежедневный бонус и добровольные рейтинги.

Визуальная плавность, совместимость устройств и корректность готового приложения пока **не подтверждены запуском**. Сгенерированные картинки — только дизайн-референсы с демонстрационными данными, не скриншоты работающего приложения.

## Защита данных и конкурентность

Telegram initData проверяется сервером; прикладная сессия непрозрачная, короткоживущая, хранится на клиенте только в памяти. Персональные ответы не кэшируются. Владелец не берётся из пользовательского payload.

Все критические игровые изменения выполняются транзакционно в PostgreSQL с порядком блокировок User → Wallet → Round, DB CHECK/unique/FK, идемпотентностью и журналом очков. Web-доступ перепроверяет тот же token и поколение аккаунта под User lock. Удаление/повторное создание с тем же Telegram ID не должно давать старому запросу доступ к новому аккаунту. Recovery ключи Mini App привязаны к account_generation.

Это реализованные механизмы, **не доказательство отсутствия уязвимостей**. Изолированный статический review нашёл и исправил ряд интеграционных гонок, но runtime/security/concurrency проверки не выполнены. До их прохождения публичный запуск не рекомендуется.

## Запуск

При восстановлении найдены существующие [npm lock](<frontend/package-lock.json>) и [Python hash-lock](<backend/requirements.lock>). После отдельного разрешения развернуть сервис на zerox-prod выполнены установка Docker из Ubuntu, сборка backend на Linux/Python 3.12 и web на Node 22, миграции новой БД и запуск контейнеров. Аудит зависимостей и тестовые suites не выполнялись. Факты и команды — в [DEPLOYED_ZEROX](<DEPLOYED_ZEROX.md>); исходный план — в [DEPLOY](<DEPLOY.md>). Секреты сюда не передавать.

Новый токен в чат не отправлять. Подключение — через защищённую конфигурацию вне репозитория. Замена старого production-бота требует отдельного подтверждения cutover-плана.
