# Переработка игрового процесса

## Подтверждённое требование

16.11.2026 пользователь выбрал: локальная механика, серверный баланс. Управление и физика на устройстве; сервер валидирует и сохраняет итог. Предыдущая реализация не принята: запрос результата плюс проигрывание анимации не является игровым процессом.

## Границы

- Не принимать клиентские balance, payout, win, species или weight как основание для начисления.
- Сервер открывает одноразовый раунд/испытание, фиксирует ставку и версию правил. Клиент выполняет симуляцию и собирает ограниченный журнал ввода; сервер независимо воспроизводит правила и вычисляет результат.
- Валидация журнала не доказывает человеческое управление. Нужны ограничения длительности, частоты, повторов, размера и начисления. Нельзя заявлять абсолютную защиту от ботов.
- Все действия остаются идемпотентными, привязаны к владельцу и версии раунда. Потеря ответа не должна дублировать списание/выплату.
- Случайные настольные игры и игры на навык не смешивать: слоты/монетка/рулетка остаются случайными, спорт и рыбалка требуют реального управления. Не маскировать RNG под навык.
- Backend production пока не менять: прежнее разрешение было web-only. Изменения нового протокола разрабатывать и проверять локально; rollout API требует согласования.

## Направление игрового интерфейса

Не страница с отчётом и формой ставки, а сцена во весь игровой viewport. HUD поверх сцены: выход, баланс, звук/пауза. Правила и журнал вторичны. Управление рядом с местом действия, touch и клавиатура, видимые прицел/траектория/натяжение, понятные промах и успех. Рыбалка: заброс с выбором точки, поклёвка, подсечка, вываживание с натяжением, садок и шесть разных видов, включая карпа.

## Текущий факт, не обещание готовности

- В исходниках удалён ручной override недели: тип определяется только выбранной датой. Пройдены переходы понедельников, Новый год, UTC+5 и TypeScript.
- Карп добавлен отдельным шестым видом (rare, 1–8 кг, 60 очков); карась сохранён. Его доля выделена из прежней rare-вероятности, агрегированная вероятность редкости сохранена. Коллекция и силуэт обновлены.
- Первый функциональный срез спорта реализован в SportsArena.tsx и arcade.ts/arcade.py: четыре игры, живое изменение прицела/силы, локальная траектория и outcome, строгий ShotInput, opt-in gameplay_version=1, серверный replay вместо RNG, 5-минутный expiry. Исходы одинаковы в 16 общих тестовых векторах. 17 Python unit-тестов, календарная регрессия и TypeScript прошли.
- В браузере выполнен локальный бросок в dev-only arcade-lab.html: ввод блокируется в полёте, локальный промах вычислен без сетевых запросов. Стенд явно не проверяет БД или настоящий баланс. Снимок desktop показал существенную визуальную недоработку: сцена слишком пустая, цель мелкая, спортивные сцены пока не прошли приёмку. Это рабочий срез, не законченная игра.
- Реализован локальный цикл рыбалки: выбор точки заброса, поклёвка, 1.2-секундное окно подсечки, 20 Hz вываживание, натяжение/слабина/сход/обрыв, пауза и resume при скрытии вкладки. FishingArena управляет сценой через ref без пересоздания WebGL на каждом такте. Клиент отправляет ограниченный журнал ввода, сервер воспроизводит его; только успешный catch сохраняет заранее скрытые species/weight/value через прежнюю транзакцию. Для новых рыболовных раундов collect запрещён, legacy collect сохранён.
- Пройдены 22 unit-теста, 16 sport + 15 fishing общих Python/TypeScript векторов, TypeScript. В браузере на dev-only стенде реально выполнены заброс и своевременная подсечка; показаны meter натяжения и progress, без удержания рыба закономерно сошла на 122-м такте, что подтвердил независимый replay стенда. В следующем проходе успешное вываживание проверено через настоящий keyboard input в mobile Edge fixture: 28 down/up переключений Space, 27 событий в журнале, улов на 286-м такте. Replay в стенде принял ввод; показан явно тестовый карп. Это browser gameplay, не проверка API или настоящего садка. Тестовая рыба в fixture помечена искусственной и не относится к production-садку.
- В третьем проходе арены разведены по видам: ближняя камера, разметка площадки/газона, полноценные кегли с реакцией на вычисленный удар, швы мяча, горизонтальный обод корзины. Убрана лишняя каталоговая оболочка в выбранной игре, старт явно называется подготовкой броска. В рыбалке исправлены оторванные рукоятка/катушка, точка лески, пирамиды заменены береговыми камнями/деревьями, добавлен связанный с берегом настил. Последний визуальный batch ещё должен подтвердить эти изменения.
- Обнаружено расширение layout на mobile fixture из-за длинного JSON output; output получил overflow-wrap:anywhere. После исправления нужен повторный замер layout clientWidth/scrollWidth (предыдущий замер innerWidth=505 нельзя выдавать за отсутствие overflow на устройстве 360px).
- Добавлены 3 новых opt-in PostgreSQL regression methods: однократная выплата спортивного раунда при повторах, запрет collect в новой рыбалке/единственный карп в садке, совместимость legacy fingerprint. Набор из 9 DB-тестов корректно загружается, но все skipped: отдельной тестовой PostgreSQL нет, команда docker на машине отсутствует. Production DB не использовалась.
- Полный локальный npm run build: TypeScript и 1605 модулей прошли, esbuild остановился на удалении собственного temp-файла в AppData/Local/Temp с Access is denied. Настройки прав не менялись; ACL repair не запускался (approval недоступен). Нужна успешная сборка в разрешённом изолированном окружении.
- Открытые задачи: финальный desktop/mobile render batch, ошибки консоли и WebGL/reduced-motion, DB-тесты в отдельном разрешённом окружении, recovery/reload, successful production build; перенос в publishing clone и scoped commit/push. Chance/strategy игры пока используют прежние контракты.
- Backend source обновлён только локально. Никаких production-изменений в этом исправлении пока нет. Не включать случайные legacy sport-раунды под видом новой механики.

## Продолжение

Рабочие изменения находятся в основной папке magtu-companion, которая сама не является git checkout. Publishing clone .local-tools/timetable-publish пока не синхронизирован, в нём сохранить чужой untracked CON. Новый протокол не требует смены DB rules_version (остаётся 1), capability хранится в public_state.gameplay_version. При пересмотре протокола не ломать fingerprint старых повторов: новые None-поля исключены при вычислении fingerprint. Только запуск dev Vite на 127.0.0.1:5178 выполнялся, production не затронут.
