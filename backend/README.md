# Backend (реализация без выполненных проверок)

Python 3.12+, PostgreSQL 16+, FastAPI, aiogram, SQLAlchemy async. В текущей сессии установка, миграции, тесты, сборка, HTTP-проверки и production-доступ не выполнялись. При восстановлении обнаружены ранее созданные локальное окружение и hash-lock, но результаты прежних запусков не подтверждены.

## Конфигурация

Все процессы стартуют из backend/. Секреты подаются окружением/секрет-хранилищем, не записываются в репозиторий.

Обязательные переменные:

- DATABASE_URL: postgresql+asyncpg URL с выделенным пользователем, непустым паролем, host и именем БД. Для приложения — роль без superuser/DDL. Для миграций — отдельная ограниченная роль владельца схемы. Дефолтные postgres/root и очевидные пароли отвергаются.
- BOT_TOKEN: настоящий токен BotFather, никогда не выводить в чат/лог.
- MINI_APP_URL: полный HTTPS URL без query/fragment/учётных данных.
- ALLOWED_ORIGINS: JSON-массив точных HTTPS origins без завершающего /, включая origin Mini App.
- ALLOWED_HOSTS: JSON-массив точных hostnames без порта, без wildcard, включая hostname Mini App. Если proxy меняет Host, добавить фактический внутренний hostname либо сохранять внешний Host.
- ADMIN_IDS (необязательно): JSON-массив Telegram ID для /status. По умолчанию пустой.

Необязательные: AUTH_MAX_AGE=300, SESSION_SECONDS=3600, SOURCE_TTL_SECONDS=900, SOURCE_MAX_AGE_SECONDS=86400, SOURCE_TIMEOUT_SECONDS=15, SOURCE_REQUEST_SPACING=1.0, WORKER_INTERVAL_SECONDS=20. Часовой пояс фиксирован Asia/Yekaterinburg.

Команды ниже — инструкция для отдельно разрешённого запуска, а не отчёт об их выполнении:

    python -m pip install --require-hashes -r requirements.lock
    alembic upgrade head
    uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-access-log
    python -m app.bot
    python -m app.worker

API и worker допускают несколько экземпляров; polling-бот только один. Открытая документация схемы: /openapi.json. /api/health показывает живость процесса, не подтверждает доступность БД/источника. Установка и миграция автоматически при импорте не выполняются.

TLS завершается на доверенном reverse proxy. Не публиковать PostgreSQL, использовать ограниченные доверенные proxy IP для forwarded headers. Не включать доверие ко всем forwarded IP. Отключить access logs с query string на прокси, исключить initData, токены, заметки и updates из логирования. Логи ограничить 14 днями во внешней конфигурации. Закрыть /docs и /openapi.json на публичном proxy при необходимости.

## Инварианты

- db.get_session не начинает/не подтверждает сервисную транзакцию автоматически; сервисы вызывают commit явно. current_user проверяет непрозрачный короткоживущий token в независимой сессии. Каждый защищённый read и mutation вызывает lock_authenticated_user в сервисной сессии: User FOR UPDATE, тот же account_generation и тот же session digest с expiry по DB clock. Это закрывает ABA удаление → повторная регистрация с тем же Telegram ID. auth.user и /me возвращают account_generation для namespace клиентских recovery keys; обычный web-путь никогда не использует trusted ID-only bot helper.
- Telegram initData проверяется HMAC-SHA256, auth_date, уникальностью полей. Одноразовый обмен защищён каноническим digest в БД; изменение порядка полей не обходит replay-защиту. В БД только SHA256 session token. Shared DB rate limits ограничивают auth по IP/Telegram ID, поиск и запросы пользователя.
- POST /notes требует отдельный request_id UUID (NoteCreate); он становится note.id. Повтор того же владельца с теми же полями возвращает запись, другой payload даёт 409, чужой UUID — 404. ON CONFLICT защищает и конкурентную коллизию между владельцами. Update/DTO не содержат request_id; миграция не требуется.
- Владелец берётся только из авторизации. Перед мутациями блокируется User и проверяется active; настройки и заметки проверяют version. Удаление блокирует User, ставит active=false, отзывает сессии и удаляет строку с CASCADE, в том числе игровые данные. Временный HMAC-маркер (без Telegram ID) запрещает повторное создание по initData до момента удаления.
- Core models не импортируют игры; Alembic и main — точки композиции. Начальная миграция заморожена, включает 6 игровых таблиц с composite owner FK и не вызывает mutable metadata.create_all.
- Настройки по умолчанию не дают согласия на уведомления и рейтинг. Пользовательские и исходные строки отправляются боту plain text, без HTML/Markdown-интерпретации.

## Источник

Адаптер читает публичный /api/v2/search и HTML .week/.day/.less. Реальная разметка группы и преподавателя, поиск и Global.js прочитаны при реализации; это не проверка готового парсера. Canonical slugs берутся из результатов поиска; ссылки отображаемых ФИО разрешаются через поиск, а не удалением пробелов. При неоднозначности разбор отклоняется и сохраняется последний достоверный снимок.

Источник работает как ограниченный public_viewer: только публичный search endpoint из клиентского JS сайта и выбранные canonical страницы, не массовый краулер. robots.txt здесь закрывает индексацию почти всего сайта; его прежняя безусловная трактовка как авторизации полностью ломала поиск. SOURCE_ACCESS_MODE=robots сохраняет явно включаемый строгий crawler-policy режим с кэшированием robots. В обоих режимах 403/429/redirect не обходятся, User-Agent не маскируется. Запросы имеют timeout, backoff, лимит 2 MB, общий DB-бюджет, coalescing поиска и lease обновления объекта. Redirect не следуется. Поиск кэшируется 5 минут, активные/домашние объекты обновляются с TTL; весь вуз не обходится. Все занятия обеих недель, времена и буквальные аудитории сохраняются; у преподавателя сливаются только полностью совпадающие совместные потоки. Сортировка и дедупликация нормализуют hash.

Первый снимок — база. Изменение публикуется только после второго совпадающего успешного получения не раньше 30 секунд. При ошибке не публикуется пустое расписание. Последний хороший кэш возвращается со stale=true; после SOURCE_MAX_AGE_SECONDS напоминания приостанавливаются. Подтверждённые предыдущие снимки удаляются через 30 дней.

week_at(instant) повторяет опубликованный JS: ceil((instant - 2024-08-19T00:00Z) / 7 дней), чётное=2. Это НЕ ISO parity. Граница — сразу после понедельника 05:00 в Магнитогорске. date_week(date) использует локальный полдень; для календарной даты занятия выбираются по этому правилу. До 05:00 понедельника current_week и шаблон этой календарной даты могут отличаться. Исключения, каникулы и достоверные замены на дату не выдумываются.

## Уведомления

Отдельные задачи обновления, планирования, отправки и очистки не блокируют друг друга сетевым ожиданием. Все категории: до пары (5/10/15/30/60), утро, вечер на завтра, изменения шаблона, конец пары с ближайшей следующей. Бот /settings управляет категориями, интервалами, временем, всеми днями, тихими часами через полночь, явной паузой, master; /mute выключает все проактивные сообщения. Права на личную отправку возникают только после пользовательского диалога с ботом, не молча из Mini App.

Очередь в PostgreSQL, уникальный dedupe, SKIP LOCKED claim, lease и fencing token. Захваченная, но ещё не отправляемая задача восстанавливается после lease. Перед sending повторно проверяются User, настройки/version, домашняя группа, snapshot hash/возраст, категория, день, тишина/пауза и срок события. Отправка — вне блокировки БД. Telegram 429 переносится на retry_after; Forbidden блокирует рассылку до возобновления диалога. Неоднозначный network/5xx/прерванный sending помечается uncertain и не переотправляется автоматически: возможна потеря одной доставки, но не массовый повтор после рестарта. Exactly-once Telegram API не обещается.

Утро/вечер/пары не догоняются после простоя; окно уже созданной задачи — до 90 секунд, до-пары не позже начала. Изменения объединяются и переносятся до разрешённого времени после тишины. Завершённые доставки хранятся 30 дней. Небольшая неизбежная гонка между последней проверкой и внешней Telegram-отправкой означает, что уже отправляемое сообщение может прийти после /mute или удаления; очередь и дальнейшие отправки отзываются.

## Модель угроз и критерии будущей проверки

| Риск | Реализованный барьер | Требуемая проверка (не выполнялась) |
| --- | --- | --- |
| Подмена Telegram / replay | HMAC, auth_date, DB replay digest и короткая opaque-сессия | Изменение подписанных полей, повтор и параллельный обмен |
| IDOR/BOLA | owner_id из current_user, owner-фильтры, User lock | Матрица двух пользователей для каждого приватного endpoint |
| XSS / инъекция сообщения | JSON DTO, plain-text Telegram, CSP/nosniff | HTML/Markdown/Unicode в имени, заметке и источнике; escaping frontend |
| CSRF / session theft | Только Authorization header, нет cookie, точный CORS, token в памяти клиента | Cross-origin mutation, отсутствие token в URL/storage/logs |
| SQL injection | SQLAlchemy параметры и autoescape поиска заметок | Метасимволы в q/id/тексте |
| SSRF / redirect | Фиксированный HTTPS host, canonical slug из каталога, запрет redirect | Схемы, encoded slash, чужой URL, redirect источника |
| Конкурентные изменения / двойная награда | User lock, optimistic version, игровые unique/check/FK и idempotency | Несколько процессов против одного owner/кошелька, удаление против мутаций |
| Worker replay / устаревший owner | DB lease/token fencing, recheck, uncertain без повторной отправки | Crash до/после sending, lease expiry, /mute/удаление во время доставки |
| Утечки через ошибки/логи | Обобщённые ошибки без input, hide_input_in_errors, логируется только тип | Перехват ошибочных запросов и секретных env; аудит proxy logging |
| Избыточные админ-права | /status только ID из env, агрегаты без личных записей | Обычный пользователь не видит служебные данные |
| Публичные backup / БД | Требование отдельной роли/приватной сети/шифрования в deployment | Проверка инфраструктуры и восстановления после отдельного разрешения |

## Границы готовности

Версии прямых зависимостей закреплены; существующий [hash-lock](<requirements.lock>) найден при восстановлении, Docker использует его с --require-hashes. Происхождение разрешения версий для целевого Linux/Python 3.12 и аудит уязвимостей в текущей сессии не подтверждались. Нет доказанной совместимости окружения, выполненной миграции или конкурентных/безопасностных испытаний. Нужны отдельно разрешённые проверки: API/DTO, Telegram HMAC/replay, изоляция владельцев, удаление против игр/worker, optimistic conflicts, parser на матрице реальных страниц, границы недели, source outage, очередь с несколькими worker и падением после sending. Production-готовность не заявляется.
