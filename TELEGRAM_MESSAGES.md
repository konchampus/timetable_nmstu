# Расписание в сообщениях Telegram

Область: только чат с ботом. Mini App, баланс, игры, HTTP API и схема БД не меняются.

## Представление

- /today и /tomorrow: нативная таблица «Пара · время / Занятие / Аудитория».
- /week: дни в нативных раскрываемых блоках; сегодняшний день раскрыт.
- /next: текущие параллельные варианты и ближайшее следующее начало. Относительное время — RichTextDateTime; абсолютные часы всегда Магнитогорск, UTC+5.
- Inline-кнопки переключают дни, недели и «Таблица / Список» в сообщении; активное состояние использует primary-style.
- «Скопировать аудитории» доступно, когда весь текст помещается в CopyTextButton без обрезки.
- Утренние, вечерние сводки и новые напоминания используют тот же форматировщик.
- Статус «Сейчас» относится к явно указанному времени формирования. Он не имитирует фоновое редактирование сообщения.
- Данные остаются двухнедельным шаблоном, не подтверждением замен. Сохранены источник, время получения и предупреждение об устаревшем кэше.

## Совместимость и безопасность

Официальная документация: https://core.telegram.org/bots/api#sendrichmessage и https://core.telegram.org/bots/api#inputrichblocktable.

В закреплённой версии aiogram новый метод ещё отсутствует. Две небольшие TelegramMethod-модели добавляют sendRichMessage и rich_message для editMessageText; граф зависимостей не обновляется.

Исходные названия передаются как данные RichText, а не исполняемый HTML/Markdown. Автоматическое распознавание сущностей в rich messages выключено. Текстовый вариант использует явные MessageEntity с UTF-16-смещениями; исходные строки никогда не становятся тегами.

Fallback происходит только после явного отказа Telegram (400/404). Timeout, сеть, 5xx и 429 не вызывают повторной отправки другим методом. Это сохраняет семантику uncertain у outbox и не создаёт дубли при неизвестном результате. Платная рассылка выключена.

Каждая страница имеет самостоятельный rich-документ и один текстовый fallback меньше 3900 UTF-16 единиц. Большой объём делится между целыми строками занятий, заголовки повторяются. Необычно длинные отдельные поля ограничены с явным указанием на полный источник.

Навигация привязана к владельцу, чату, сообщению, случайному ключу и сроку 30 минут. При обновлении ключ меняется под блокировкой. Старые результаты поиска и чужие/устаревшие кнопки не изменяют настройки или чужое расписание.

Миграция БД не нужна. Новые outbox-задания хранят version=1 document и текст для отката. Старые задания не переписываются и не переотправляются: их дедупликация, lease-token, account-generation и сроки сохраняются. Для многостраничного события каждая страница имеет отдельный dedupe. В legacy-событие дополнительные страницы не дописываются.

## Границы проверки

16.11.2026 официальный API распознал sendRichMessage: запрос без chat_id вернул 400 «chat_id is empty». Получатель не задавался; сообщений пользователям эта проверка не отправляла. Это подтверждение наличия метода, а не полноценная приёмка клиентского отображения.

Автоматические тестовые suites без запроса пользователя не запускать. После выпуска ручная приёмка в актуальном Telegram: /today, /week, /next; кнопки дня, следующей недели и «Список / Таблица»; копирование аудиторий. Не рассылать демонстрационные сообщения произвольным пользователям.
